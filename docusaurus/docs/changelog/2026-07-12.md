# 2026-07-12: GitOps-managed Tailscale ACLs

**Sat, Jul 12, 2026.** Moved the tailnet ACL policy from console-only editing
to a version-controlled `policy.hujson` synced by GitHub Actions
(`tailscale/gitops-acl-action`), and scoped LAN subnet-route access to
tagged admin devices instead of every tailnet peer. Full rationale in
[ADR 0007](../decisions/0007-tailscale-acl-route-scoping.md).

## What changed

- Added `policy.hujson` at the repo root: `tagOwners` for
  `tag:homelab-gateway` / `tag:homelab-admin`, `grants` scoping
  `10.0.0.0/22` to `tag:homelab-admin` only (everyone else gets
  `autogroup:internet`, exit-node routing, but not LAN reach),
  `autoApprovers` so the gateways can self-approve their route/exit-node
  advertisement once tagged.
- Added `.github/workflows/tailscale-acl.yml`: `test` on PRs touching
  `policy.hujson`, `apply` on push to `main`.
- Created an OAuth client in Tailscale's Trust credentials, scoped to
  `Policy File: Read+Write` only (cannot touch devices, users, DNS, or
  anything else in the tailnet).
- Added `TS_OAUTH_ID`, `TS_OAUTH_SECRET`, `TS_TAILNET` as GitHub Actions
  secrets on the repo.

## What was verified before changing anything

- Confirmed via the admin console (Machines) that this is the tailnet with
  `raspberrypi` and `vpn-gateway`, not a different account.
- Confirmed the tailnet was still on Tailscale's **unrestricted default**
  policy (no custom rules, no tags on any of the 4 devices), so there was
  nothing existing to accidentally clobber by introducing a managed policy.

## What's still manual (by design)

Tags don't exist until `policy.hujson` merges and the `apply` job runs, so
tagging `raspberrypi`/`vpn-gateway` as `tag:homelab-gateway` and the
operator's own admin device as `tag:homelab-admin` happens **after** merge,
not in this PR. See ADR 0007's rollout steps. Skipping the admin-device
tagging step would leave the operator's own device with exit-node-only
access under the new policy. Order matters.

## Gotcha

The live tailnet uses the newer `grants` policy syntax, not the older `acls`
array; Tailscale's own in-console example template still shows `acls` as a
commented-out legacy example alongside the real `grants` block. Wrote
`policy.hujson` in `grants` syntax to match what the tailnet actually uses.

## Removed the ollama LXC (code only)

Dropped `module "ollama"` from `terraform/envs/prod/main.tf`, its
`ansible/inventory/hosts.yml` entry, `services/prod/ollama/`, the
`ollama.example.com`/`chat.example.com` Caddy blocks, its stack page,
and its Uptime Kuma monitor. This PR is code-only; the actual
`terraform destroy -target=module.ollama`, the AdGuard rewrite cleanup, and
the `/data/ollama` + `/data/open-webui` data check happen as a separate,
explicitly-confirmed step, not automatically on merge.

## Scaffolded OpenClaw

Rebased and reworked `feature/openclaw` (PR #19, forked before ollama was removed;
rebasing onto `main` first avoided silently reverting it). The OpenClaw image uses a
single `anthropic` provider backed by the Claude API with an API key from the
environment (see the [OpenClaw stack page](../stack/openclaw.md)).

Also dropped the embedded `node_exporter` sidecar from the compose file;
the branch forked before that got centralized into
`services/_shared/node-exporter/`, so it still had the old copy-pasted
pattern. Added the LXC's Prometheus target instead.

## Provisioned openclaw live (LXC 604, node2, 10.0.3.13)

Ran the full runbook end to end: `terraform apply -target=module.openclaw`,
`docker.yml`, `caddy.yml`, `adguard-rewrites.yml`, pushed
`OPENCLAW_GATEWAY_TOKEN` (generated) via `make push-secret`, `node-exporter.yml`,
`prometheus.yml`. Verified live: `https://openclaw.example.com` → 200,
node_exporter target `10.0.3.13:9100` up in Prometheus.

**Found live, not in review:** there's no `openclaw.yml` service-specific
playbook, so the generic `deploy.yml` (which only copies
`docker-compose.yml` + `.env`) failed with `failed to read dockerfile`:
openclaw is a locally-built image like `caddy` and needs its
Dockerfile + `openclaw.json` synced too. Added
`ansible/playbooks/openclaw.yml` (same full-directory-sync pattern as
`cobalt.yml`) and pointed the runbook at it instead.

**Second bug found live:** the committed `openclaw.json` had a custom
`meta.note` field (documentation text); turns out `meta` is reserved for
OpenClaw's own `lastTouchedVersion`/`lastTouchedAt`/`wizard` bookkeeping,
not a freeform notes field. The extra key failed config validation and
crash-looped the gateway (`Gateway failed to start: Invalid config ...
meta: Invalid input`). Fixed by running `openclaw doctor --fix` against
the container's state volume to repair it in place, then removing the
`meta` block from the committed config so a future rebuild doesn't
reintroduce the same crash loop. Logged as a gotcha in `AGENT.md`.
