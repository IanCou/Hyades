# 2026-07-06: tailscale LXC resource bump

**Mon, Jul 6, 2026.** Live health check of the tailscale LXC (VMID 116,
node1, the subnet router + exit node) surfaced a tight root disk and
low memory. Bumped both to match the other core LXCs.

## What changed

| Resource | Before | After  | Why                                                            |
| -------- | ------ | ------ | -------------------------------------------------------------- |
| Disk     | 2 GB   | 4 GB   | Root was at **89%** (203 MB free); matches adguard             |
| Memory   | 256 MB | 512 MB | 168 MB used, ~87 MB free, **no swap**; matches other core LXCs |

CPU left at 1 core. The container's loadavg read high (1.2–1.9), but
`vmstat` showed it **90%+ idle with 0% steal**; the inflated loadavg is
the usual LXC artifact where `/proc/loadavg` reflects the whole Proxmox
host, not the container. Actual per-process CPU was ~0.4%, so no CPU
change was warranted.

## Disk breakdown

The 89% wasn't Docker: images totaled only 404 MB. The bulk was the
base OS: `/usr` 860 MB, `/var/lib` 551 MB (docker/containerd overlay),
plus ~193 MB of reclaimable apt cache in `/var/cache`.

## Files touched

- **`terraform/envs/core/main.tf`** (`module.tailscale`): `memory`
  256 → 512, `disk_size` 2 → 4.
- **`AGENT.md`**: added a _Git conventions_ section (feature branches,
  human-sounding commits, no AI co-author trailers).

## Apply

`terraform plan -target=module.tailscale` confirms **update in-place,
0 to destroy**: both changes apply live without recreating the
container (memory via `pct set`, disk via `pct resize`, which grows the
ext4 filesystem in place):

```bash
cd terraform/envs/core
terraform apply -target=module.tailscale
```

## Gotcha

Reaching the LXC over Tailscale needed a warm-up: the first `tailscale
ping` / SSH to `vpn-gateway` (100.64.0.1) timed out during NAT
hole-punching, then succeeded once the direct path established. Don't
read the first cold-path timeout as the host being down.
