# 2026-07-18: cobalt.tools LXC (Tailscale/LAN only)

**Sat, Jul 18, 2026.** Provisioned a self-hosted [cobalt](https://cobalt.tools/) media-download API in prod, deliberately kept off the public route.

## LXC 218: `cobalt` (node1)

Terraform-managed (`terraform/envs/prod/main.tf`), `10.0.2.17`, 2 cores / 1 GB / 8 GB, same profile class as `searxng` (light, stateless). `ghcr.io/imputnet/cobalt:11` + a watchtower sidecar for auto-updates, no volumes; cobalt keeps no state of its own.

**Access posture matches AirTrail's precedent, corrected mid-session.** First pass wrongly assumed "no Caddy block" was what kept AirTrail off the public internet, and skipped the Caddyfile entirely. That's not the actual mechanism: public reachability for `*.example.com` is gated by a **Cloudflare Tunnel** (`cloudflared` on the Caddy LXC) whose ingress hostnames are set directly in Cloudflare's dashboard, outside this repo, not by whether a Caddy block exists. AirTrail _does_ have a Caddyfile block and a real TLS cert; it's just never been added to the tunnel's ingress list, and has no public DNS record (confirmed empty `dig airtrail.example.com @1.1.1.1`, vs. `immich.example.com` which resolves to Cloudflare's edge IPs). Corrected cobalt to match exactly: added `cobalt.example.com { reverse_proxy 10.0.2.17:9000 }` to the Caddyfile, redeployed Caddy, updated `API_URL` to `https://cobalt.example.com/`, regenerated docs, and reconciled AdGuard, which added `cobalt.example.com → 10.0.1.10` (Caddy) alongside the existing `cobalt.example.internal → 10.0.2.17` (direct LXC IP, for SSH). Verified `https://cobalt.example.com` serves over LAN with a valid cert (`curl --resolve ... :443:10.0.1.10` → `200`), has no public DNS record, and `.local` SSH still works.

## Upstream's example watchtower image doesn't work on current Docker Engine

Copied cobalt's [official docker-compose example](https://github.com/imputnet/cobalt/blob/main/docs/examples/docker-compose.example.yml) as a starting point, which pins `ghcr.io/containrrr/watchtower`. It crash-looped: `client version 1.25 is too old. Minimum supported API version is 1.40`; that image's Docker client predates this host's Engine (API 1.55). `containrrr/watchtower` is effectively unmaintained; swapped to `nickfedor/watchtower`, the actively-pushed fork (confirmed via Docker Hub's tag API: 360 tags, last push today), which came up healthy immediately. Worth remembering next time a compose example ships a `containrrr/*` image.

## Prometheus scrape targets are still hand-maintained, and can drift silently

`services/core/prometheus/prometheus.yml` is a static target list, not derived from Terraform/inventory; adding a new LXC doesn't automatically get it scraped, and nothing fails CI if you forget (found by inspection: `searxng` is missing from the `prod` job too, from before this session). Added `10.0.2.17:9100 # cobalt` by hand and restarted the Prometheus container via an ansible ad-hoc `docker_compose_v2` call (`playbooks/prometheus.yml` syncs the config file but has no handler to reload/restart on change; also a pre-existing gap). Confirmed `up` via `/api/v1/targets` afterward. A future improvement: generate this list the same way `adguard_rewrites.py` derives its DNS set, from Terraform + inventory, so this class of drift becomes structurally impossible instead of just newly-noticed.

## Provisioned from a worktree: local secrets aren't checked out there

Ran the whole thing from `.claude/worktrees/cobalt-prod-lxc` to keep the working session isolated from the main checkout. `terraform.tfstate`/`terraform.tfvars`, `ansible/.vault_password`, and `ansible/group_vars/all/vault.yml` are all gitignored (state and credentials, correctly not in git) and so don't exist in a fresh worktree; pointed `terraform apply`/`plan` at the main checkout's real state/tfvars via `-state=`/`-var-file=`, and Ansible at the real `.vault_password` via `--vault-password-file=`, rather than copying secrets into the worktree. Confirmed the targeted `terraform plan` was clean (1 to add, 0 to change, 0 to destroy) before applying, so the rest of prod's state was never at risk.
