# 2026-07-19: cobalt web frontend, split from the API

Added cobalt's web frontend alongside the API deployed yesterday; hitting
`cobalt.example.com` was only ever returning the API's JSON response,
since no frontend had been deployed.

## Upstream ships no Docker image for the frontend

Cobalt's `web/` package is a SvelteKit app built with
`@sveltejs/adapter-static`, a fully static build, but upstream's own
`Dockerfile` only builds the API stage (`@imput/cobalt-api`); the frontend is
deployed to Cloudflare Pages instead (`web/wrangler.jsonc`), never as a
container. Wrote [`services/prod/cobalt/Dockerfile.web`](https://github.com/IanCou/Hyades/blob/main/services/prod/cobalt/Dockerfile.web):
clones the cobalt monorepo at a **pinned commit** (`a636575b0`, the exact
commit the running `ghcr.io/imputnet/cobalt:11` / `11.7.1` API image was
built from, so frontend and API can't drift out of sync), builds the pnpm
workspace with `WEB_DEFAULT_API`/`WEB_HOST` as build-time args (baked into
the JS bundle, not runtime env; confirmed by grepping the built bundle
inside the container for the API hostname), and serves the static output via
nginx.

## Split into two hostnames, matching upstream's own topology

The frontend is a client-side SPA that calls the API directly from the
browser; it can't be reverse-proxied under the same hostname/path as a
JSON API without conflicting routes. Mirrored upstream's real split
(`cobalt.tools` frontend talks to `api.cobalt.tools`):

- `cobalt.example.com` → `cobalt-web` (nginx, port 8080)
- `api.cobalt.example.com` → `cobalt` API (port 9000), new Caddy block

Same access posture as before (and as AirTrail): both hostnames are fronted
by Caddy with a real TLS cert, but neither has a public DNS record or a
Cloudflare Tunnel ingress rule, so neither is reachable outside LAN/Tailscale.
Verified via `dig ... @1.1.1.1` (empty for both) and `curl --resolve` through
Caddy (both return valid responses over LAN).

## Custom builds need their own playbook, not the generic deploy.yml

`deploy.yml` only syncs `docker-compose.yml` + `.env` to the remote host,
fine for pulled images, but a `build:` directive referencing a local
Dockerfile has nothing to build from once only those two files exist on the
target. `services/core/caddy/` already solved this with a dedicated
`playbooks/caddy.yml` that also syncs the Dockerfile; wrote
`playbooks/cobalt.yml` following the same pattern (`build: always` on the
`community.docker.docker_compose_v2` task) instead of extending the generic
playbook.

## LXC resized for the build

Bumped LXC 218 from 1 GB/8 GB to 2 GB/16 GB (in-place Terraform update, no
recreate; confirmed via `terraform plan` showing "will be updated in-place"
before applying): a pnpm install + Vite/Rollup build across the whole
cobalt workspace needs more headroom than the API-only profile had, and the
build runs on the LXC itself (`docker compose build` via Ansible).
